# v0.2 telemetry security demonstration

This is an **offline demonstrator**. It uses the Phase 1 telemetry contract, the Phase 3 allowlist normalizer, and the Phase 2 Ed25519 signer. It does not watch a host, enroll an agent, or send events over the network.

## What it proves

On one machine, with no extra services:

1. Raw synthetic observations are reduced by `normalize_observation`. Extra keys are discarded. `192.0.2.10` becomes `[ip]`.
2. The Phase 1 models accept the resulting `process_started`, `process_exited`, and `network_connection_observed` envelopes.
3. A document with an extra `command` field is rejected by that same validator.
4. `generate_signing_key()` creates an in-memory Ed25519 key pair.
5. `sign_event()` signs the complete envelope. The signature is not an envelope field.
6. `verify_event()` accepts the original event and signature.
7. The same signature is rejected after the payload or `target_id` is changed.

A valid signature proves that the matching private key signed that envelope. It does not prove the agent is authorized.

## Architecture and execution flow

```text
demo.py            terminal formatting and process exit status
demo_runner.py     measured stages; calls envelope and signature APIs
demo_data.py       synthetic raw observations
normalize_observation  Phase 3 allowlist redaction
TelemetryEnvelope  Phase 1 validation
sign_event /
verify_event       Phase 2 Ed25519 over canonical JSON
```

Stage order: redact and normalize raw dictionaries → validate (including one invalid document) → generate keys → sign → verify originals → tamper copies → print counters taken from that run.

Tampering copies an already signed event with `json.dumps` / `json.loads`. The payload copy changes `comm` from `python3` to `nginx`, which remains a legal Phase 1 value, so rejection comes from Ed25519, not from schema validation. The identity copy assigns a new `target_id`. The original dictionary is not written.

## Prerequisites

Python 3.12 and the locked dependencies. PostgreSQL is not required for the demonstrator. It is required for the full pytest suite.

## Installation

From the repository root, using the same workflow as the rest of the project:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.lock
```

## Exact command

```bash
PYTHONPATH=packages/telemetry/src .venv/bin/python -m synapse_telemetry.demo
```

`make demo` runs the same module after setting `PYTHONPATH` for the local packages.

Exit status is 0 only when every required stage observed the real PASS or REJECTED outcome. An unexpected exception is reported as FAIL, not PASS.

## Expected output

The terminal prints a `SYNAPSE-CRS` banner, seven stages, and a summary. Look for:

- Stage 1 discarded extra fields and `remote_address: 192.0.2.10 → [ip]`
- three generated event types
- `validation=PASS` on those events
- `validation=REJECTED` on the invalid document
- `Algorithm: Ed25519` and a `sha256:` public-key fingerprint
- three signatures with `raw_length=64`
- original verification `PASS`
- `Original event integrity: VALID`
- `Modified payload integrity: REJECTED`
- `Modified identity integrity: REJECTED`
- `Demonstration result: PASS`

Public-key fingerprints, event IDs, and signature strings change every run. Private keys are not printed.

## Synthetic versus real

| Real | Synthetic / not implemented |
|---|---|
| Phase 3 allowlist redaction | Event bodies (pid, ports, comm) |
| Phase 1 `TelemetryEnvelope` validation | Collection from `/proc` |
| Phase 2 Ed25519 generate / sign / verify | Network traffic, agents, HTTP, PostgreSQL |
| Tamper rejection by `verify_event` | Live endpoint monitoring |

Identifiers and timestamps are generated at runtime and must still match the contract (UUID version 4, `YYYY-MM-DDTHH:MM:SS.ffffffZ`).

## Current limitations

The demonstrator does **not** implement:

- live endpoint monitoring
- a Linux telemetry collector
- agent enrollment
- trusted agent identity
- HTTP ingestion
- database persistence
- autonomous threat reasoning
- runtime mitigation
- in-memory hotpatching

Those remain later phases. Do not present this command as a deployed sensor.
