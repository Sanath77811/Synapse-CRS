# Data model

Timestamps are `timestamptz`. Identifiers are UUIDs generated by the API.

## targets

| Column | Notes |
| --- | --- |
| `id` | Primary key |
| `name` | Operator label, 1–200 characters |
| `owner` | Accountable owner, 1–200 characters |
| `scope` | JSON object: `environment`, `assets`, `description` |
| `authorization_status` | Stored value: `active` or `revoked` |
| `authorization_expiry` | Eligibility also requires this instant to be in the future |
| `allowed_capabilities` | JSON array from the v0.1 allowlist |
| `created_at`, `updated_at` | Set by the API |

The API reports a derived status of `expired` when the stored status is `active` and the expiry is not in the future, and `invalid` when the stored status is neither `active` nor `revoked`.

## cases

A case belongs to one target. `state` is one of the ten pipeline names. `created_by` is the authenticated actor.

## case_transitions

One row per accepted move: `from_state`, `to_state`, `actor`, `reason`, `created_at`. The HTTP view always reports `executed: false` because v0.1 does not store or run an effect.

## audit_events

| API field | Column |
| --- | --- |
| `id` | `id` |
| `sequence` | `sequence` |
| `timestamp` | `event_timestamp` |
| `actor` | `actor` |
| `event_type` | `event_type` |
| `target_id` | `target_id` |
| `case_id` | `case_id` |
| `payload` | `payload` |
| `previous_event_hash` | `previous_event_hash` |
| `event_hash` | `event_hash` |

`sequence` is an implementation field. It gives the chain a total order. The first event uses the genesis previous hash of 64 zero characters. The hash is SHA-256 over a canonical JSON object containing the previous hash, event id, sequence, UTC timestamp, actor, event type, target id, case id, and payload.

## audit_chain_state

A single row (`id = 1`) holds `next_sequence` and `head_hash`. It is bookkeeping. Chain verification replays `audit_events` and does not trust this row.
